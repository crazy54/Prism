# Prism Control architecture

Prism Control (`com.jeremyfhall.prismcontrol`) is a native Windows Stream Deck plugin in C# / .NET 10. The Stream Deck app starts `bin/PrismControl.exe` (the manifest's `CodePath`/`CodePathWin`), and the exe speaks the raw plugin WebSocket protocol. It turns the deck into a control surface for the PC, drawn in Prism's Refraction look. The Corsair Galleon 100 SD and the Stream Deck + are first-class targets; every other Stream Deck works too.

This document covers the structure, the runtime, the key decisions, and how to build, test and pack. The contract for domain engineers is in [authoring-actions.md](authoring-actions.md). The data API for the sibling plugin is in [api.md](api.md).

## 2. Runtime overview

```
 Stream Deck app (Qt)                              Prism Control (one process)
 ─────────────────────        ws://127.0.0.1:port  ─────────────────────────────────────────────────────────────────
                         ──────────────────────▶  StreamDeckConnection ─ receive loop (never blocks)
  willAppear, keyDown,                              │ text
  dialRotate, touchTap,                             ▼
  sendToPlugin, ...                               InboundParser ──▶ ActionEvent ──▶ ActionHost ──▶ instance.Deliver(e)
                                                    │ plugin events (global settings, devices, wake, deep links)
                                                    ▼                                    │ per-instance mailbox
                                                  GlobalSettingsStore, DeviceDirectory   ▼ (serial, ordered)
                                                  PluginEvents → modules               Action handlers (KeyAction/DialAction)
                                                                                         │ SetImage / SetFeedback / SetTitle / Layout
                                                                                         ▼
                                                                                       UpdateScheduler (budget, latest-wins, diff)
                                                                                         ▲ Pump(now)
                         ◀──────────────────────  writer task ◀── bounded queue ◀───── UpdatePump
  setImage, setFeedback,                           (send timeout, rate limits)          other commands (setSettings, showOk,
  setSettings, ...                                                                      sendToPropertyInspector, ...)

 Prism plugin (prism-27) ── HTTP GET + Bearer ──▶ DataApiServer (127.0.0.1:random) ◀── DataRegistry ◀── modules publish
                                                     control.json in %APPDATA%\Prism\control
```

### 2.1 Start-up and shutdown

1. **Arguments.** `Program` parses `-port -pluginUUID -registerEvent -info`. Developer modes are `--emit-manifest`, `--list-actions`, `--selftest` and `--version`. Bad or missing arguments exit 2 with a hint.
2. **Logging.** `PluginHost` opens the file log at `%APPDATA%\Prism\control\logs\prismcontrol.log` (one shared-read stream, rolled at 5 MB). Warnings and errors are also sent to the app log via `logMessage`, rate-limited.
   **Safe mode.** `PRISM_CONTROL_SAFE_MODE=1` (set by the fake host and E2E) is read once. The log then says `**** SAFE MODE ON ****`, the host forces `PRISM_CONTROL_MACROS_DRY_RUN=1` in its own environment before modules load, modules and actions see `SafeMode = true` (§3.2, authoring-actions.md § Safe mode), and `ProcessLauncher.Start` starts nothing. `/v1/health` reports `safeMode` and `macrosDryRun`.
3. **Environment.** `QT_*`/`QTWEBENGINE_*` variables inherited from the Qt host are removed from our process, so apps we launch scale normally.
4. **Core objects.** It builds the device directory from `-info`, the scheduler, the connection, the update pump, the global-settings store, the service registry and the data registry.
5. **Discovery.** Module assemblies are loaded (§3.2) and actions discovered (§3.3). Errors are logged and the bad action is skipped.
6. **Data API.** The API starts on `127.0.0.1:0` and `control.json` is written. Demo providers start if `PRISM_CONTROL_DEMO_DATA=1`.
7. **Modules.** Each `IPrismModule.Initialize(context)` runs inside a try/catch, so a failing module never takes the plugin down.
8. **Connect.** The connection opens, registers, and asks for the global settings. The run lasts until the app closes the socket.
9. **Shutdown** (the app closes the socket, Ctrl+C/SIGTERM/ProcessExit, or reconnecting gives up):
   - every instance gets a final `willDisappear` and is disposed;
   - modules that implement `IAsyncDisposable` are disposed (2 s each);
   - `control.json` is deleted (only if it is still ours) and the API stops;
   - the socket is closed with NormalClosure (1 s), and the log is flushed.
   - Exit code 0, or 1 if reconnecting gave up.
   - If the app is killed, its job object (KILL_ON_JOB_CLOSE) kills us without a graceful shutdown. `control.json` can then be stale; clients handle that (api.md §1).

## 3. Components

### 3.1 Protocol layer (`src/PrismControl/Protocol/`)

**`LaunchArgs` / `RegistrationInfo`** parse the command line and `-info`: application version, `devicePixelRatio`, and `devices[{id,name,type,size}]`. Unknown device types map to `DeviceType.Unknown`; type 14 (MCP Deck) is recognized.

**`InboundParser`** turns every message into a typed record:

| Group | Events |
|---|---|
| Action events (Core records) | `willAppear`, `willDisappear`, `keyDown`, `keyUp`, `dialRotate`, `dialDown`, `dialUp`, `touchTap`, `didReceiveSettings`, `propertyInspectorDidAppear`, `propertyInspectorDidDisappear`, `sendToPlugin`, `titleParametersDidChange` |
| Plugin messages | `didReceiveGlobalSettings`, `deviceDidConnect`, `deviceDidChange`, `deviceDidDisconnect`, `systemDidWakeUp`, `applicationDidLaunch`, `applicationDidTerminate`, `didReceiveDeepLink`, plus anything unknown (logged at debug level) |

**`Outbound`** builds the commands:

| Group | Commands |
|---|---|
| Scheduled | `setImage`, `setTitle`, `setFeedback`, `setFeedbackLayout` |
| Direct | `setState`, `showOk`, `showAlert`, `setTriggerDescription`, `setSettings`, `getSettings`, `sendToPropertyInspector` (with `action`) |
| Plugin-level | `setGlobalSettings`, `getGlobalSettings`, `openUrl`, `logMessage`, `switchToProfile` (context = registration id, plus `device`) |

JSON goes out without HTML escaping. Tests pin the exact shapes.

**`StreamDeckConnection`** wraps `ClientWebSocket` and always connects to `ws://127.0.0.1:<port>`. `localhost` costs about 2 s on this PC because the app listens on IPv4 only. Its properties:

- **Watchdog-safe.** The receive loop only reads and hands text to the host, which parses and posts it to a mailbox. It never awaits user code, so the app's pings are always answered. One writer task drains a bounded queue (1,024 frames). Each frame has a 5 s send timeout: a wedged socket is aborted and reconnected, never waited on. Unscheduled commands are capped at 100/s (burst 200) and `logMessage` at 10/s, so a buggy loop cannot flood the app. Render updates come pre-budgeted from the scheduler, which applies back-pressure through the bounded queue.
- **Reconnect.** A drop without a close frame triggers reconnect-and-re-register, with backoff from 250 ms to 2 s, for up to `PRISM_CONTROL_RECONNECT_SECONDS` (10 s by default). Then the plugin gives up and exits; the app relaunches plugins. On every disconnect, all instances are torn down and the scheduler is reset. The app sends `willAppear` again after re-registration (verified in the lab and by the E2E test).
- **Clean stop.** A close frame from the app means "stop", whatever its status code. The plugin answers NormalClosure and shuts down.

### 3.2 Modules (`IPrismModule`)

Each domain project declares `[assembly: PrismModule(typeof(XModule), MonitorApplications = [...])]`.

The exe's csproj turns **every `ProjectReference` except Core** into `[assembly: AssemblyMetadata("PrismModule", "<name>")]` (the `PrismModuleMetadata` target). At runtime `ModuleLoader` calls `Assembly.Load` on each name. That is needed because the compiler drops references the exe never uses directly, so nobody maintains a list. Modules get an `IModuleContext`:

- `Log`, `Data`, `Services`, `GlobalSettings`, `Events`, `Devices`, `Time`;
- `SafeMode` (a default interface member, so test contexts need not implement it; actions have the same value as `ActionBase.SafeMode`);
- `ShutdownToken`;
- `PluginDirectory`;
- `DataDirectory` (`%APPDATA%\Prism\control\modules\<name>`);
- `OpenUrl`.

`MonitorApplications` feeds the manifest's `ApplicationsToMonitor` (Spotify declares `Spotify.exe`).

### 3.3 Action framework (`src/PrismControl.Core/Actions/`)

- **Discovery.** `ActionRegistry.Discover` scans the module assemblies and the exe for non-abstract classes with `[StreamDeckAction("com.jeremyfhall.prismcontrol.<…>", Name = …, Controllers = …, Icon = …, Layout = …)]`. The rules live in Core (`ActionValidator.Scan`), so domain tests call the same code. It validates:
  - the UUID prefix and lowercase pattern, and that `Name` is set;
  - the base class against `Controllers` (Encoder actions must derive `DialAction<T>`);
  - a public parameterless constructor;
  - the layout id/path pattern and `#RRGGBB` StackColor;
  - that image paths have no extension;
  - duplicate UUIDs.

  Invalid actions are skipped, with errors logged, and `--emit-manifest` fails.
- **Instances.** `ActionHost` keeps one instance per context. It creates it on `willAppear` (`Activator.CreateInstance`), binds it, and routes every event into the instance's **mailbox**: a serial async queue, so handlers for one instance never overlap while different instances run concurrently. `Post(...)` lets other threads (SMTC and Core Audio callbacks run on the thread pool) get onto the mailbox. A handler exception is logged and the mailbox keeps going. Handlers slower than 2 s are logged as warnings.
- **Typed settings.** `KeyAction<TSettings>` / `DialAction<TSettings>` deserialize the `settings` of every event with System.Text.Json: camelCase, numbers and bools read from strings (PI inputs send strings), enums as camelCase strings, and **nullable annotations respected** (`RespectNullableAnnotations`). `ActionJson.ReadOrDefault` repairs what it can: a property whose value is invalid (a null for a non-nullable type, a wrong type) is removed at the error's JSON path and keeps its default, up to 16 times; an invalid array element or anything else gives `new TSettings()`. Each repair is logged. Writes never throw on a forced null (they retry without the check). Global sections are read the same way. `SaveSettings()` sends `setSettings`.
- **Gestures.** The framework adds `OnKeyPress`, `OnKeyLongPress` (at 500 ms while held), `OnDialPress`, `OnDialLongPress` and `OnTouchTap` on top of the raw events. Dial long-press is **only raised where `SupportsDialLongPress`** (Stream Deck +), never on Galleon, whose ~4 s hold is consumed by the device. If an action does not override the long-press handler, a long hold is an ordinary press.
- **Device awareness.**
  - `DeviceInfo` has the type, grid, `IsGalleon` and `IsPlus`.
  - `DeviceCapabilities` holds the RESULTS.md truths: encoder slots, dial layers, touch, dial long-press, max ticks/event (Galleon ±12), key pixels, encoder display size (Galleon about 360×180).
  - `EncoderPlacement` maps Encoder coordinates to the Galleon quadrant or the Stream Deck + strip segment.
- **Render loops.** `StartRenderLoop(render, idleInterval, activeInterval)` posts ticks into the mailbox, never piles them up, switches to the active interval for 2 s after any input, and stops on `willDisappear`.
- **Multi-actions.** Instances inside multi-actions never render; their `setImage`/`setFeedback` calls are dropped.

### 3.4 Update scheduler (`Core/Scheduling/UpdateScheduler.cs` + `UpdatePump`)

Every `setImage`, `setFeedback`, `setFeedbackLayout` and `setTitle` goes through one scheduler, so that Prism Control stays inside its share of the Stream Deck app's ~230–300 updates/s. Above that ceiling the app queues without limit and its watchdog kills plugins that flood it.

| Rule | Default | Why (RESULTS.md) |
|---|---|---|
| Global token bucket | **60 updates/s**, burst max(4, budget/4) = 15; configurable via global settings `core.updateBudget` (clamped 5–240) | Shared with the Prism plugin (200/s) |
| Latest-wins | per context and per (state, target) for images and titles | The app never drops stale frames |
| Feedback merge | keys merge, newest value per key | `setFeedback` payloads are partial |
| Only changes | a payload equal to what was last sent to that context is dropped (per feedback key) | Most 1 Hz stats frames are identical |
| Layout ordering | `setFeedbackLayout` goes before the feedback queued after it; feedback queued before it is dropped; a new layout resets the per-key "last sent" | Values belong to a layout |
| Interactive tier | for 1.5 s after any key/dial/touch input on a context: served first, up to 30 Hz per context | Dial feedback ≤ 30 Hz while turning |
| Normal tier | ≤ 10 Hz per context | The Elgato guideline is ~10/s per key |
| Background tier (idle/stats) | ≤ 2 Hz per context, served last | Stats at 1–2 Hz |
| First draw | `willAppear` invalidates the "last sent" cache and boosts the context to interactive for 0.5 s | A profile switch draws every key at once |

`UpdateScheduler` is pure and thread-safe; the caller passes the time in, which makes it deterministic in tests. `UpdatePump` is an async loop: it pumps up to 32 due updates, writes them to the connection (awaiting queue space), then sleeps until `NextWake` or an enqueue signal. It never busy-polls.

`/v1/health` and the Diagnostics action expose the counters: `sentLastSec`, `coalesced`, `skippedUnchanged` and latency.

**Verified:**

- **Unit tests.** 12 keys × 60 fps produce at most 61 updates in any 1 s window. The tier rates hold, and the interactive tier jumps the queue.
- **E2E, published exe.** 28 contexts each asking for 60 fps (1,680/s requested) gave at most 62 in any 1 s window and an average of ≥ 45/s, with every context served. After the PI set `core.updateBudget` to 30, the maximum was ≤ 32/s.
- **Fake-host CLI run.** 28 contexts with random input averaged 40.8/s, and the worst 1 s window was 57.

### 3.5 Rendering (`Core/Render/`)

- **`SvgDocument`** emits only the Qt-safe subset from `results/svg-support.md`:
  - hex colors, with translucency as `fill-opacity`/`stroke-opacity`/`stop-opacity`/`opacity` (`Paint.Parse` converts `rgba()`/`#rrggbbaa` and rejects `hsl()`);
  - linear and radial gradients;
  - **luminance masks instead of clipPath** (`Mask`, `MaskRoundedRect`, `MaskCircle`);
  - feGaussianBlur glows with `color-interpolation-filters="sRGB"`;
  - the `transform` attribute;
  - embedded PNG/JPEG images, with the box computed from the real pixel size (the app ignores `preserveAspectRatio`).

  `Key()` is a square 144 viewBox and `Dial()` is 200×100. Output goes through `ToDataUri()` as `data:image/svg+xml,…`. A frame is capped at **300 elements** (`SvgBudgetExceededException`). Numbers are invariant culture with 2 decimals. Debug builds lint every frame.
- **`SvgLint`** checks any SVG or data URL against the lab rules: errors for things that render wrong on the device, warnings for things that are silently ignored. The test harness lints every frame an action produces.
- **`StrokeFont`** is a geometric monoline font drawn for this project; there is no font file. Its glyph space has a capital height of 100 units:
  - digits are tabular;
  - it covers A–Z, small caps for lowercase, Latin diacritics via Unicode decomposition (with stacked and attached marks: Vietnamese, ogonek, horn, comma below), Ł Đ Þ Ħ ı ß, Greek and Cyrillic, ASCII and typographic punctuation (including `@` `` ` `` `{}` and quotes), currency, ©®™, math (± ÷ ≈ ≠ ≤ ≥ ∞), fractions, super/subscripts, music signs and simple shapes; compatibility forms (fullwidth, ligatures, circled and Roman numerals) draw as their plain letters;
  - text is processed per grapheme. Scripts it does not draw (CJK, kana, Hangul, Arabic, Hebrew, Indic, Thai) and emoji become **one visible replacement box per grapheme**, never a silent drop, and never an exception (wave 1 threw on any emoji). `Supports`/`Unsupported` let callers pick another presentation. Invisible format characters are skipped;
  - it measures, fits and ellipsizes.

  Each text run becomes **one stroked `<path>`**, which is pixel-exact in the app; live `<text>` falls back to one sans face with RGB fringes. Sizes are CSS-like, with capital height = 0.72 × size, so the token sizes carry over (value 44, label 22, dial value 34, dial label 14).
- **`ImageInfo` / `DataUri`** probe the PNG/JPEG/GIF/WebP headers (no decoding) and build data URLs.
- **Tokens.** `Render/Tokens/Refraction.g.cs` is **generated** from `Prism-ds/design/tokens.json` by `tools/PrismControl.TokensGen`. It provides:
  - `Refraction.Night` / `.Day` palettes: `color.*` and the plain-color `rf.*` entries, with `rgba()` split into hex + opacity;
  - the deck key material gradient stops, edge and ink, and the 12-stop spectrum (ink, vivid, wash, sheen);
  - `Refraction.Deck` (canvas, safe area and type constants), `Radius` and `Motion`.

  The header records the tokens version and SHA-256. A test regenerates the file in memory and fails if the checked-in file is stale; `build.ps1` runs `TokensGen --check`.
- **`Core/Art`** (designer) holds the starting-point `KeyArt` (material, lit edge, hue index, value/label, glyph keys), `DialArt` (panel and meter) and `Glyphs` (a generic music note, never the Spotify logo; speaker, sliders, bolt). `Hues` assigns a spectrum hue per domain (placeholder choices).

### 3.6 Dial layouts (`layouts/`, `Core/Layouts/`)

| File | Items (key: type) | Use |
|---|---|---|
| `prism-canvas.json` | `canvas`: pixmap [0,0,200,100] | Draw the whole frame yourself (best Refraction fidelity) |
| `prism-value.json` | `bg` pixmap (z0); `label`, `value` text; `bar` bar (z1) | Quick native-text value + bar |
| `prism-media.json` | `bg`; `art` pixmap 76×76; `line1`, `line2` text; `progress` bar | Now playing (art left, outside the text) |
| `prism-dual.json` | `bg`; `label`; `bar_a`, `bar_b` | L/R, CPU/GPU |

All four validate against `plugin-layout.schema.json` and the app's geometry rules: inside 200×100, unique keys, no overlap within a zOrder. No item is keyed `title` or `icon`, because the user can override those. `Layouts.*` constants are pinned to the JSON by a test. `Feedback` builds payloads: implicit text/number values, explicit items (colors validated hex, opacity snapped to 0.1 steps, gradient strings) and pixmaps from an `SvgDocument`.

On the **Galleon**, each of the four screen widgets shows the full 200×100 canvas, uniformly scaled to about 360×180. Author at 2:1.

### 3.7 Property-inspector bridge (`pi/`, `Core/PropertyInspector/`)

- **`pi/lib/prism-pi.js`** (no dependencies, offline) implements `connectElgatoStreamDeckSocket` (always `127.0.0.1`) and `window.PrismPI`:
  - `settings`, `setSettings(patch)`, `onSettings`;
  - `global.get`/`set`/`setKey`/`onChange`/`loaded` (writes wait for the first `didReceiveGlobalSettings`, because `setGlobalSettings` replaces the whole object);
  - `refreshOptions(names)`;
  - `send(type, data)` and `request(type, data) → Promise`, with `requestId` matched to `pi.response`;
  - `on(type, fn)`, `openUrl`, `log`;
  - declarative binding: `data-setting="name"` (two-way, debounced) or `data-setting="global:<section>.<key>"` (a key of a global-settings section), `data-state="key"`, and auto-forms into `#prism-form`.
- **The message convention** is `{ type, data, requestId? }` over `sendToPlugin`/`sendToPropertyInspector`:
  - `pi.ready` → the plugin answers `pi.hello` with action, context, controller, coordinates, device flags (`isGalleon`, `isPlus`, `hasTouch`, `dialLongPress`), theme, settings, form and state;
  - `pi.response` answers requests;
  - `pi.state` pushes status;
  - `pi.refresh` `{ lists?: [...] }` makes the PI re-request `optionsFrom` lists (`ActionBase.RefreshPropertyInspectorOptions`), and a repeated `pi.hello` rebuilds the form (`RefreshPropertyInspectorForm`).
- **Pages.** `pi/default.html` renders the form an action returns from `DescribeForm()` (a `PiForm` with text, text area, number, range, checkbox, select (static or `optionsFrom` a request), multi-select (a checklist, optionally ordered, bound to a string array), button, info and heading). A saved value missing from a list is shown as unavailable instead of silently becoming the first option. `pi/template.html` shows the pattern for custom pages. Verified in headless Chrome with a fake socket (21 checks: global writes wait for the load and merge, refresh keeps the selection, ordering, max, debounced multi-line text).

### 3.8 Data API (`src/PrismControl/DataApi/`, `Core/Data/`)

A raw `TcpListener` HTTP/1.1 server on `127.0.0.1:0`, with a 256-bit token in `%APPDATA%\Prism\control\control.json`. A raw listener rather than `HttpListener` means no http.sys URL ACLs and exact control over `Host`. It refuses:

- any `Origin` (403), a `Host` other than `127.0.0.1:<port>` (421), and a wrong token (401);
- non-GET/HEAD methods (405) and request bodies (400).

It also rate-limits, supports keep-alive, sends ETag/304 and no CORS. This mirrors `elgato-mcp/DESIGN.md` §6.3.

`DataRegistry` pre-creates the v1 topics. Modules **claim** a topic:

- **push:** `Claim(source, cadence)` returns a `DataPublisher<T>` with `Publish`, `Clear`, `IsDemanded` and `DemandStarted`;
- **pull:** `ClaimPull(source, fn, cacheFor)` or `ClaimProvider(IDataProvider<T>)`.

The first real claim wins, and it replaces a demo claim. Payloads are the Core contract classes, serialized by a source-generated context (camelCase, nulls written, UTC-ms timestamps, no HTML escaping) once per publish. Demand tracking lets expensive producers (metering) run only while polled. The first request after idle waits up to 250 ms for the first frame. The full spec, with payloads, units, cadence, errors and versioning, is [api.md](api.md); a copy is at `aaa-prism-ds/prism-control/API.md`.

### 3.9 Global settings

One JSON object in the app, split into sections. `core` is architect-owned:

```json
{ "core": { "updateBudget": 60, "theme": "night", "reducedMotion": false } }
```

`theme` is `"night"` or `"day"`. Each domain owns a section: `audio`, `systeminfo`, `spotify`, `eq` (backend: `sonar` or `apo`) and `macros`. `IGlobalSettings.GetSection<T>`/`SetSection` merges and sends the whole object. **Secrets never go here** (they are plain text and exported with profiles): use `Core.Security.SecretStore` (DPAPI CurrentUser via crypt32; the managed `ProtectedData` is not in the base runtime).

### 4.1 Test approach (decision)

We use a **tiny in-repo runner** (`tests/PrismControl.Testing`) instead of MSTest/xUnit, so the repo has **zero NuGet packages**, test-only ones included. Every test project is a console exe:

- `[Test(Category = "unit"|"integration"|"e2e", TimeoutMs = …)]` marks public methods (void or Task);
- tests run sequentially (deterministic; the E2E tests own processes and ports);
- `IDisposable`/`IAsyncDisposable` fixtures are disposed per test;
- `--filter`, `--category` and `--exclude` select tests, and the exit code is non-zero on failure.

`ActionHarness<TAction>` runs one action with a recording channel and a `ManualTimeProvider` (deterministic long-presses and render-loop cadences), and `AssertFramesAreDeckSafe()` lints every frame. What we give up: IDE test-explorer integration. Running a test exe is one command, and output is plain `PASS`/`FAIL` lines.

**Counts today (wave 2):**

- 102 core tests (101 unit, 1 integration);
- 405 domain tests (378 unit, 27 integration: read-only probes of this PC, skipped with `build.ps1 -SkipIntegration` or `--exclude integration`): Audio 89, SystemInfo 48, Spotify 84, Eq 58, Macros 80, Cooling 46;
- 12 E2E tests against the published exe. These cover the Galleon and Stream Deck + profiles, the stress budget, the PI round trip, reconnect after a drop, clean exit with `control.json` removal, every data-API endpoint with auth (including Node's `fetch`), `--selftest`, the bundle/manifest, and **safe mode**: `/v1/health` reports `safeMode` and `macrosDryRun` before any test places an action, a Macros hotkey press reaches only the dry-run sink, and the `fake-host` CLI refuses a real action without `--allow-real-actions` and otherwise places only the safe set.

### 4.2 Publish, trimming and size (decision)

- **NuGet.** Restore needs `nuget.config` (`<clear/>` + nuget.org) because this PC has no package sources. It only fetches Microsoft platform packs the SDK references implicitly: `Microsoft.NETCore.App.Runtime.win-x64` (self-contained), `Microsoft.Windows.SDK.NET.Ref` (the windows10.0.22621.0 projection: `Microsoft.Windows.SDK.NET.dll` is about 26 MB, plus `WinRT.Runtime.dll` about 0.5 MB) and `Microsoft.NET.ILLink.Tasks` (when trimming). There are no third-party packages.
- **Default:** self-contained, single-file, compressed, win-x64, **not trimmed**, embedded PDB.
  - The exe is **42.4 MiB** and the `.streamDeckPlugin` **37.3 MiB**.
  - Correctness over size: domain code may use reflection-based JSON, classic `[ComImport]` COM and arbitrary WinRT APIs. None of those can be broken by trimming in this build.
- **Opt-in `-Trim`** (`-p:PrismTrim=true`): `PublishTrimmed`, `TrimMode=partial` (only framework and projection assemblies are trimmed; ours are rooted), `BuiltInComInteropSupport=true`, `JsonSerializerIsReflectionEnabledByDefault=true`.
  - The exe is **12.3 MiB**.
  - Verified today: `--selftest` passes (classic COM, source-generated COM, WinRT activation, SMTC) and **all 9 E2E tests pass** against the trimmed exe.
  - The remaining ILLink warnings are the expected reflection uses (typed settings, discovery), which partial mode keeps working.
  - **Recommendation:** switch the release build to `-Trim` once the domain modules are real and their own tests plus the E2E suite pass on a trimmed build. CsWinRT generic instantiations used only through reflection are the residual risk.
- **Never installed.** `pack` writes `dist/`; double-clicking the bundle is the user's or the lead's step.

## 5. Security notes

- **The data API** is loopback only, uses a 256-bit token, and rejects bad `Host`/`Origin`; it has no write endpoints. The token lives in `control.json`, in the per-user `%APPDATA%` (user-only ACL by inheritance), and it is never logged.
- **Another process running as the same user** can read the token. That is out of scope; the API is read-only, so the blast radius is reading stats and now-playing data.
- **Secrets** (Spotify tokens) use DPAPI CurrentUser with per-secret entropy, under the module data folder. They are never stored in action or global settings.
- **The plugin process** runs at Medium IL inside the app's job. Children we launch break away, which is desired. `ProcessLauncher` keeps their working directory off the plugin folder.
- **Fake input never reaches the PC.** The fake host and E2E always launch in safe mode, place only the samples and Diagnostics unless a UUID is allowed explicitly (`FakeHostSafety`, `FakeHostOptions.AllowRealActions`, `--allow-real-actions`), and check `/v1/health` reports safe mode first. Module write paths honor `SafeMode` from wave 3 (§6).

## 6. Known limits and open questions

1. **Galleon key raster and widget aspect** are unconfirmed until the device photos arrive (RESULTS §8). We author keys at 144 and widgets at 2:1, as RESULTS.md advises.
2. **`Software.MinimumVersion` is 7.1** (SDK 3; broadest). The Galleon itself needs app 7.2+. Raise it to 7.6 if we ever use Neo.
3. **The Diagnostics action is visible** in the actions list, which is useful for hardware QA (its stress mode load-tests the budget on real devices; its PI shows safe mode). Hide it (`VisibleInActionsList = false`) before release if wanted. The five samples are hidden since wave 2 and stay as safe E2E fixtures.
4. **Placeholder icons.** The prism-with-spectrum placeholder echoes a famous album cover; the designer should replace it with Prism's own mark.
5. **SMTC/Spotify attribution** (Spotify's "attribution with marks" versus TEAM.md's "no Spotify logo") needs a lead decision (see research/spotify.md). The framework draws no logos.
6. **Trimmed release** (§4.2) is a lead decision, once the domains land.
7. **Safe mode is wired in the framework, not yet in the modules.** Wave 3: each domain owner gates its write paths on `IModuleContext.SafeMode` (authoring-actions.md § Safe mode); Macros also reads `SafeMode` instead of relying on the forced dry-run variable. Until a module does, the fake host refuses to place its real actions without `--allow-real-actions`.
8. **Non-Latin text on keys.** The stroke font draws Latin, Greek and Cyrillic; other scripts and emoji show replacement boxes. A live-`<text>` fallback (Arial, which the lab found works) could show CJK through Qt's font fallback, but that is unverified on the device: a lab test with a CJK/Hangul/Arabic `<text>` key would decide it.
9. **`/v1/health` gained `safeMode` and `macrosDryRun`** (additive). api.md and `aaa-prism-ds/prism-control/API.md` need the two fields (lead, with the `/v1/cooling` entry).
10. **Meters at 30 Hz** (Audio): the normal tier caps a context at 10 Hz. Add a "live" tier only if idle 30 Hz meters are wanted; probably not.
